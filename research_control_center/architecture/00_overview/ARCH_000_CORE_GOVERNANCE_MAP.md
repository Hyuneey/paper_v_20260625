# ARCH-000 Core / Governance Map

## Scientific core

Candidate discovery, relation profiling, construction evidence, T0/T1/T1-B/T2, the executed task verifier, COMMON-42 utility descriptors, the real D1 runtime, D0, D2, and episode/event metrics.

## Governance

Data custody, split policy, authorization, private-value resolution, freezes, receipts, and result-integrity controls. These enforce scientific boundaries but are not detector logic.

## Reporting

Professor packages, thesis exports, and RCC views consume public-safe frozen metadata. They do not create scientific results.

## Reference / legacy

`src/paperworks/dsl`, `verification`, `runtime`, `planning/refiner.py`, historical `e2e`, and `experiments/argos_reproduction` remain compatibility or reference paths. Current v6 frozen executions use task-specific bridges under `src/paperworks/v6`.

## Test infrastructure

Synthetic contract, mutation, differential, custody, and independent integrity tests are evidence about implementation behavior. Test execution is not scientific execution or independent reproduction.

Several domains intentionally have parallel layers: canonical Rule v1 contracts, task-specific executed construction/runtime bridges, and governance receipts. ARCH-004 through ARCH-008 must review these boundaries before any refactor.
