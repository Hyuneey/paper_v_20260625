# 교수님 피드백과 현재 대응

| 교수님 제안·질문 | 현재 대응 | 남은 공백 | 요청드리는 결정 |
|---|---|---|---|
| LLM이 왜 필요하며 임의 규칙·수치를 어떻게 통제하는가 | LLM은 typed/bounded 규칙 구조만 제안합니다. 숫자는 정상 데이터에서 고정하고 deterministic verifier가 최종 승인합니다. 런타임에는 LLM이 없습니다. | verifier feedback 자체가 성능을 높였다는 근거는 없습니다. | agentic 비교를 핵심 결과보다 구성 통제의 보조 분석으로 둘지 |
| TSFM을 활용할 수 있는가 | **현재 사용하지 않았습니다.** 우선 검증 가능한 규칙 파이프라인을 완성했습니다. | TSFM 효과와 비용을 비교하지 않았습니다. | 필수 비교인지 향후 연구인지 |
| 이상탐지 모델과 규칙을 왜 결합하는가 | PCA-SPE를 기준 탐지기로 두고 규칙이 그 미탐을 보완하는지 직접 평가했습니다. | 규칙은 D0 미탐 3/3을 찾았지만, 현재 fusion은 0/3만 회복했습니다. | combined-improvement 주장을 제외하고 보완성 분석으로 기여를 한정할지 |
| 결과가 무엇을 설명하는가 | source transition, target response, lag/horizon, 만족 trace로 관계 위반을 보여줍니다. | 사람 대상 유용성 평가는 하지 않았고 causal root cause를 증명하지 않습니다. | 현재 규칙-trace 인터페이스를 주 설명 방식으로 인정할지 |
| 중요한 시간 구간을 먼저 선택할 수 있는가 | 전이 시점과 관계 horizon으로 시간 범위를 국소화합니다. | **ARTIST식 segment proposal/selection은 구현하지 않았습니다.** | ARTIST식 상위 localization 모듈을 추가할지 |
| 동적 관계를 다루는가 | source step 이후 1/5/10/30/60초의 target response를 모델링합니다. | 복잡한 다단계 dynamics와 feedback loop는 범위 밖입니다. | 현재 delayed-response rule family의 범위를 수용할지 |
| 도메인 지식 의존이 큰가 | 변수 역할 metadata로 후보 범위를 제한하고 숫자는 정상 데이터로 결정합니다. | 변수 역할 검토와 P1 범위 선택에는 사람의 공정 지식이 남습니다. | 이를 한계로 명시하고 현재 범위를 유지할지 |
| 설명을 재현할 수 있는가 | 동일한 검증 규칙과 입력은 동일한 만족 trace와 결과를 냅니다. | human usefulness와 신뢰도 연구는 없습니다. | 사람 대상 평가는 후속 연구로 둘지 |

## 방향 변경의 요점

초기 방향의 “LLM이 좋은 규칙과 설명을 자유롭게 생성”하는 문제를,
“LLM을 사용하더라도 구조 제안만 허용하고 숫자·검증·실행을
결정론적으로 통제”하는 문제로 바꾸었습니다. 이에 따라 현재 연구의
중심은 새 탐지기나 자연어 생성 자체가 아니라 **검증 가능한 시간
규칙의 구성과 실행 근거**입니다.

현재 설명 인터페이스는 ARTIST와 동일하지 않으며, TSFM도 구현되지
않았습니다. 이 공백은 완료된 작업으로 표현하지 않습니다.
