# 교수님 보고용 1페이지 요약

## 연구 질문

**정상 운전 데이터에서 발견한 시간적 변수 관계를, LLM이 임의 수치나 실행 코드를 만들지 못하도록 통제하면서 실행 가능한 규칙으로 구성·검증하고, 이상탐지기의 미탐을 보완할 수 있는가?**

연구의 중심 기여는 새 탐지기 자체가 아니라 **그래프 유도 후보 선별 → 정상 데이터 수치 권한 → 제한된 규칙 구성 → 결정론적 검증 → LLM 없는 런타임과 추적 설명**이다.

## 왜 방향이 바뀌었나

교수님 피드백과 ARGOS 재현 검토를 통해 LLM이 임의 Python/임계값을 만드는 구조는 과학적 통제와 재현성이 약하다는 문제가 분명해졌다. 그래서 연구의 초점을 “LLM이 좋은 규칙을 자유롭게 생성하는가”에서 “LLM을 쓰더라도 제한된 구조만 제안하게 하고, 숫자·검증·실행은 결정론적으로 통제할 수 있는가”로 옮겼다. TSFM과 ARTIST식 세그먼트 선택은 현재 구현 범위에 포함하지 않았다.

## 구현된 것

- HAI 23.05 P1 Boiler의 144개 후보쌍과 META/STAT/GDN 후보 경로
- 정상 데이터 기반 관계 프로파일링과 42개 확인 관계(COMMON-42)
- T0/T1/T1-B/T2 규칙 구성 비교, 숫자 참조 권한, 결정론적 verifier
- LLM-free D1 규칙 런타임과 source–target–lag–trace 기반 설명
- PCA-SPE 기준 탐지기 D0와 두 결합 정책 D2 V1/V2
- 이벤트 recall, 정상 FAR episode/hour, 미탐 회복률 평가와 결과 무결성 감사

| D2 V1 | 0.7857142857142857 (11/14) | 0.7056194750975128 | 0/3 |

D0와 D1은 10개 이벤트를 함께 탐지했고, D0만 1개, D1만 3개, 둘 다 놓친 이벤트는 0개였다. 규칙 신호의 보완성은 확인됐지만 결합 정책은 이를 유용한 성능 향상으로 바꾸지 못했다. 14개 이벤트만으로 통계적 우월성을 주장하지 않는다.

## 가장 중요한 해석

`RULE_SIGNAL_PRESENT_BUT_CURRENT_FUSION_UTILITY_UNSUPPORTED`

- 지원: 규칙 구성·검증·실행이 가능하고, INNER에서 D1은 D0의 미탐 정보를 보완한다.
- 지원 안 됨: 결합 방법이 D0보다 낫다, 규칙 전용이 운용 가능하다, 일반화된다, 인과적 root cause를 찾는다.
- V2는 시간 기억을 추가했지만 recall은 늘지 않고 정상 FAR 부담만 V1보다 커졌다.

## OUTER가 없는 이유

허가된 1회 OUTER 시도는 test2 feature custody 접근에서 **바이트를 읽기 전에** 거부됐다. feature bytes 0, semantic parse 0, label access 0, D0/D1/D2 실행 0, prediction/metric 없음이다. 이는 부정적 OUTER 결과가 아니라 **OUTER 결과 부재**이며 일반화는 미확인이다.

## 교수님께 요청드릴 네 결정

1. 논문 기여를 “결합 탐지기 향상”이 아니라 “그래프 유도 규칙 구성과 결정론적 검증”으로 승인할지
2. 실행 규칙과 satisfaction trace를 주 설명 인터페이스로 인정할지, ARTIST식 구간 선택을 요구할지
3. 새 독립 OUTER 연구를 먼저 할지, INNER 범위 주장으로 논문 초안을 먼저 쓸지
4. PCA-SPE만 첫 기준 탐지기로 충분한지, 더 강한 기준선 하나를 추가할지

권고 기본안은 **`THESIS_FIRST_PENDING_PROFESSOR_FEEDBACK`**이다.
