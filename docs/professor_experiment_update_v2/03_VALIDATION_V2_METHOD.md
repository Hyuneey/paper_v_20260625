# VALIDATION V2 방법

## 고정된 순서

1. 정상 데이터 역할과 feature/file contract 확인
2. candidate discovery 정책 실행
3. relation profiling·confirmation
4. normal-only numeric authority 선택·freeze
5. evidence pack과 bounded construction
6. deterministic Formal V4 admission·runtime authorization
7. durable label-blind prediction freeze
8. development label lease와 common metric evaluation
9. result-integrity audit

## 과학적 분리

- deterministic validity는 구조·authority·provenance를 검사하며 성능을 증명하지 않습니다.
- normal-only selection에는 test1 label을 사용하지 않습니다.
- test1은 frozen policy의 development observation에만 사용합니다.
- final held-out은 DG-05의 새로운 preregistration 전까지 접근하지 않습니다.
- PILOT V1 artifact는 어떤 V2 단계에서도 덮어쓰지 않습니다.

## 현재 authority

VALIDATION V2는 canonical RuleV1/VerifierV1 equivalence를 주장하지 않습니다. 실행 authority는 Formal V4이며 relation, numeric registry, evaluator, config, feature/file/sampling contract, horizon과 execution context를 exact replay합니다.

> VALIDATION V2에서는 실제 실행과 무결성이 이미 확인된 V4 관계 규칙
> 표현과 검증·재생·수치 결속·실행 권한 체계를 공식 실행 기준으로 사용한다.

정확히는 `CanonicalRuleDescriptorV4`, V4 task validity, replay/conformance,
Utility V4 numeric binding, portfolio freeze, runtime authorization, durable
prediction custody, versioned metric/result-integrity controls가 실행 적격성을
결정합니다. Canonical `RuleV1`과 `VerifierV1`은 인접한 계약 component로
남지만 V4 runtime을 직접 승인하지 않습니다. canonical→V4 bridge는 최소
논문 경로에서 선택하지 않았습니다.

## 현재 중단점

승인된 HAI 23.05 normal train1~4 custody를 코드 기반 공식 materialization 경로로 복구했습니다. 이 custody 아래 EXP-01·EXP-01B·EXP-02 정상 데이터 실행을 완료했으며, test1과 모든 label은 아직 열지 않았습니다.
