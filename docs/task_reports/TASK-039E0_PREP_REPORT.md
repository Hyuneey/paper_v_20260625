## Deterministic validity

The project-owned label-free verifier skeleton checks:

- closed schema/DSL structure;
- allowed source and target identities;
- exact relation, source/target direction, and horizon binding;
- approved numeric bundle, reference, and origin binding;
- unsupported variables and numeric literals;
- fixed structured runtime logic with no free-text runtime behavior;
- prohibited data references;
- deterministic proposal serialization;
- construction arm, evidence, and budget provenance;
- absence of premature rule materialization or authority claims.

It returns only `admissible` or `rejected` plus bounded machine-readable
reasons. It does not inspect label or utility input, use chain-of-thought,
materialize Rule v1/v2, accept a canonical rule, or grant runtime authority.

## Validity, utility, outcomes, and runtime

Validity is deterministic, label-free, and construction-time. Utility remains
a distinct future stage requiring explicit label/outcome authorization and
cannot influence validity acceptance.

The metric policy separately defines rule-construction success, `no_rule`
rate, valid-rule rate, runtime abstention rate, and explanation/rule coverage.
`no_rule` is not automatically a system failure and is not abstention.

Runtime remains LLM-free. A proposal or admissible preparation result cannot
authorize runtime; separate later governance is mandatory. Rule v1 behavior
is unchanged, Rule v2 is not created, and generic decrease-direction support
in the preparation envelope does not authorize a canonical decrease rule.
