# Reproducibility assessment

| Level | Rating | Basis | Remaining barriers |
|---|---|---|---|
| RESULT TRACEABILITY | STRONG | canonical remote ref, frozen public predictions/metrics, exact configs, integrity artifacts, professor cross-links | audit history is large and should be navigated through the artifact index |
| SAME-MACHINE REPRODUCIBILITY | MODERATE | source, environment manifest, local preservation assets, deterministic kernels, and private authorities can support allowed non-sealed replay | private locator configuration, process-local factory custody, and optional provider/dependency setup remain operational prerequisites |
| FRESH-MACHINE PORTABILITY | WEAK | public source and documentation can be cloned and inspected | official raw HAI acquisition, private artifact bootstrap, private numeric/model authorities, locator configuration, and environment reconstruction are not one-command portable |

Raw data and private scientific payloads are intentionally excluded from Git;
that exclusion is not a defect. The release is a traceable research checkpoint,
not a self-contained public reproduction capsule. The environment manifest and
source-only archive help, but private/bootstrap instructions and a tested clean-
machine setup would be required for a stronger portability rating.

OUTER status is consistently represented: one scientific attempt was consumed,
one feature-custody access was attempted, feature byte reads and semantic parses
were zero, label accesses were zero, D0/D1/D2 executions were zero, predictions
and metrics do not exist, and generalization is unconfirmed.
