# Blocker root-cause analysis

| Class | Representative pattern | Effect on science |
|---|---|---|
| SCIENTIFIC_BLOCKER | initial infeasible binary/discrete source morphology; D2 fusion produced no incremental utility | changed scope or scientific conclusion and is explicitly reported |
| IMPLEMENTATION_BUG | execution/finalization/control-flow defects | stopped a task; did not change a frozen result when remediation was bounded |
| CUSTODY_OR_ENVIRONMENT | private locator, factory/process custody, and OUTER feature-custody rejection | limited execution or portability; OUTER produced no scientific result |
| ARTIFACT_SCHEMA | accounting-field, blocker-schema, and report-model drift | delayed certification/reporting after evidence already existed |
| REPORTING_OR_PROVENANCE | Markdown separator, self-hash, bundle/receipt, and render defects | affected audit/report serialization, not metric values |
| OVERSTRICT_GOVERNANCE | retroactive status/lifecycle requirements for legacy blockers | created non-scientific gates and was later classified non-gating |

The late D2 integrity and OUTER histories are dominated by infrastructure,
schema, custody, provenance, and overstrict-governance issues rather than
changes to scientific conclusions. Recurring causes were duplicated schemas,
task-specific models drifting from producers, machine-local locator assumptions,
and excessive coupling between evidence validation and report finalization.

The scientific conclusions materially affected by evidence remain simple:
D1 is complementary but noisy; D2 V1/V2 do not improve D0 on INNER; OUTER is
unobserved. Further blocker-remediation machinery is not recommended.
